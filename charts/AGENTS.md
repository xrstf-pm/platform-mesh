## Repository Description
- `charts/` contains the Helm charts used to deploy Platform Mesh and supporting components (imported from the former `helm-charts` repository).
- The main moving parts are charts under `charts/`, generated chart documentation, the OCM component definitions under `ocm/` and the local developer setup under `local-setup/`. How releases work is described in `docs/release/process.md`.
- Read the org-wide [AGENTS.md](https://github.com/platform-mesh/.github/blob/main/AGENTS.md) for general conventions.

## Core Principles
- Keep chart changes small and reviewable. Values, templates, chart versions, dependencies, and generated docs are tightly coupled.
- Prefer existing `task` workflows over ad-hoc Helm commands.
- Update generated chart docs and dependencies when chart inputs change.
- Keep this file focused on agent execution and repository-specific constraints.

## Project Structure
- `charts/`: Helm charts, values, templates, tests, chart locks, and chart READMEs.
- `charts/.docs-templates/`: templates used by `helm-docs` to generate chart documentation.
- `ocm/`: `component-constructor.yaml` (aggregate + third-party wrappers), `charts/<chart>.yaml` (per-chart OCM settings), `versions.yaml` (third-party pins), `components.yaml` (components built in this repo). The full graph is generated by `hack/release/build-aggregate.sh`.
- `local-setup/`: scripts, manifests, kustomize overlays, and e2e assets for local Platform Mesh development.
- `.github/workflows/`: `ci.yml` (chart lint/unittest/docs), `release.yml`, `prerelease.yml`, `e2e-localsetup.yml`.
- `charts/Taskfile.yaml` (`task charts:*`) and `local-setup/Taskfile.yaml` (`task local-setup:*`): automation entrypoints.

## Architecture
This is a deployment and packaging repo, not a service runtime.

### Chart model
- Each chart under `charts/` owns its `Chart.yaml`, `values.yaml`, templates, optional test values, and generated README.
- Several charts depend on other charts in this repository; chart version bumps and dependency updates need to stay aligned.
- `helm-docs` generates chart README content from chart metadata, values, and templates.

### Local setup and OCM model
- `local-setup/` is the supported path for bootstrapping and testing a local Platform Mesh instance.
- `hack/release/build-aggregate.sh` builds the OCM component graph for releases, prereleases and local-setup alike.
- Charts are published by the next Platform Mesh release/prerelease that includes their version; component versions are immutable, so every chart change needs a version bump (enforced by `ct lint` in CI).
- Workflow changes can affect chart publishing and full platform bootstrap behavior.

## Commands
- `task charts:lint` — run chart-testing lint against charts.
- `task charts:test` — run Helm unit tests for all charts.
- `task charts:helmtest-update` — update Helm unittest snapshots when expected output changes.
- `task charts:docs` — regenerate chart documentation with `helm-docs`.
- `task charts:update-changed` — regenerate docs, update dependencies, and update snapshots for changed charts.
- `task charts:update` — regenerate docs and update dependencies for all charts.
- `task charts:validate` — run test, docs, dependency update, lint, and OCI packaging checks.
- `task charts:vulnerability` — run kube-linter against charts.
- `task charts:oci` — package charts into the local `oci/` output directory.
- `hack/release/build-aggregate.sh --version X --generate-only` — write the OCM constructor for the current tree without publishing.

## Code Conventions
- Bump the chart version for any chart whose rendered behavior changes.
- Run `task charts:docs` after changing chart metadata, values, README templates, or generated chart docs.
- Run `task charts:update-changed` after changing chart dependencies or values that affect snapshots.
- Keep templates readable; prefer chart-local helper templates over duplicated complex logic.
- Keep secrets and credentials out of values files, workflows, and local setup scripts.

## Generated Artifacts
- Chart READMEs are generated by `task charts:docs`; do not hand-edit generated sections when a source value/template change is required.
- `Chart.lock` files should be updated through Helm dependency workflows.
- Helm unittest snapshots should be updated through `task charts:helmtest-update` or `task charts:update-changed`.

## Do Not
- Skip chart version bumps for behavior-changing chart edits.
- Hand-edit generated chart documentation as a substitute for changing chart metadata or values.
- Commit local secrets from `.secret/`, generated binaries from `bin/`, or local OCI output.
- Introduce new chart publishing or local setup paths when existing `task` targets cover the workflow.
- Change OCM signing or release behavior casually; treat `.github/workflows/release.yml`, `hack/release/build-aggregate.sh` and `ocm/component-constructor.yaml` as production changes. Component and reference names in the OCM graph are a contract.

## Hard Boundaries
- Ask before changing chart publishing, OCM packaging, or local setup bootstrap semantics.
- Be especially careful with changes under `.github/workflows/`, `ocm/`, `hack/release/` and `local-setup/`.
